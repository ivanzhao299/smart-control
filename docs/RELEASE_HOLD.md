# 持久发布暂停标记

项目根目录的 `RELEASE_HOLD` 存在时，新版后端、seed、自动更新、播放器watchdog、两个开机启动入口以及普通CI发布入口拒绝继续。标记不根据时间、PID或启动次数自动失效，不读取内容决定放行；它与8小时过期的现场控制台 `MAINTENANCE.flag` 独立。

## 不能把标记当作停写证明

标记不会终止已经运行的后端、转码进程、Office COM、watcher、播放器或其它部署进程。旧版本脚本也不认识新标记。持续停写必须由独占发布控制方负责：

1. 确认实际主机、项目、数据库、媒体目录与运行版本，盘点计划任务及所有写入进程。
2. 在维护窗口隔离外部入口，禁止自动更新和自动拉起，建立持久标记；停止并等待所有相关进程真正退出。
3. 持续保持上述隔离，使用真实核验回调执行配套备份、恢复演练和迁移。不能用固定返回true、单次端口探测或标记存在代替核验。
4. 成功后在入口仍隔离的条件下选择准确新版本，受控移除标记、启动并验收；最后恢复入口与原先启用的任务。
5. 任一步失败保留标记及配套恢复包，禁止因标记太旧而删除，也禁止自动启动旧代码读取新私人数据。

当前实现仅为新入口防重启组件。生产独占控制方、Windows进程/计划任务实际验证与受控激活仍未接线；普通CI入口在标记存在时也被禁止，不能用它充当控制方。本地未创建实际标记，未暂停生产或本地正在运行的服务。
