# 阶段 1 数据权威与数据库收敛退出审计

> 审计日期：2026-09-17
> 审计基线：`88ba5f3`
> 范围：生产代码、40 个数据库迁移、运行时路径、启动生命周期、部署门禁、数据库/媒体恢复证据
> 结论：代码侧达到阶段 1 退出条件；异机迁移恢复基线纳入发布门禁。普通定时备份的连续异机 RPO 仍属于阶段 3。

## 1. 退出结论

1. 业务配置的运行时权威源已经收敛到 SQLite 关系表或 `RuntimeConfigStore`。生产服务不再读取或写入退役 JSON。
2. 数据库结构只由 `backend/src/migrations` 修改。非迁移生产 TypeScript 中的 `CREATE/ALTER/DROP TABLE|INDEX|TRIGGER` 由自动门禁禁止。
3. 系统品牌、视频绑定等关键权威记录缺失或校验失败时拒绝启动或拒绝保存，不再用默认值静默重建，避免掩盖数据丢失。
4. 所有启动生命周期钩子均已逐项分类并固定为自动测试白名单。新增钩子必须先进入审查，不能悄悄恢复启动建档或修复写入。
5. 数据迁移恢复包包含同一写入隔离窗口内的 SQLite 与完整媒体副本、文件清单和 SHA-256。发布验证成功后，按目标提交号把对应恢复包追加式复制到异机并重新校验。
6. 退役 JSON 仍保留为历史迁移与恢复证据。它们不再是应用回退源，不会覆盖 SQLite 新修订。

## 4. 启动与保存门禁加固

`assertSchemaReady` 在原有迁移、列、触发器、签名配置和启用管理员检查之外，增加：

- `system_branding_v2` 必须且只能存在 id=1；
- `video.binding` 必须且只能存在一份 schema v1 当前文档；
- 当前文档 revision 必须为正数，内容 SHA-256 必须匹配；
- 当前 revision 必须在历史表中有且只有一条相同 SHA-256 的记录。

检查失败时应用明确拒绝启动，要求从已验证备份恢复，不执行启动修复。系统品牌保存接口也不再创建缺失 singleton。

## 5. 备份边界与异机复制

### 5.1 两类备份的边界

- 普通定时备份：每 6 小时保存 SQLite 和运行时证据，当前仍位于现场 `D:` 盘。
- 迁移恢复包：数据迁移前在停止写入的窗口中保存 SQLite 和完整媒体副本，并完成隔离恢复演练。
- 异机迁移基线：生产验证成功后，通过受限动作 `gk9000-offsite-backup <commit>` 查找该提交对应的恢复包，复制到跳板机 `/var/backups/smart-control/<release-id>`。

### 5.2 失败关闭规则

- 只接受完整 40 位提交号和固定 `release-*` 目录名；
- 目标目录追加式写入，已有目录只重新验证，绝不覆盖或自动清理；
- 拒绝符号链接、特殊文件、越界相对路径和传输中发生变化的文件；
- 重新校验 SQLite 大小、SHA-256、`integrity_check`、`foreign_key_check`；
- 重新生成媒体逐文件清单并与原清单逐项比较；
- 只在全部检查通过后原子发布目录并写 `offsite-receipt.json`；失败只清理本次私有临时目录。

### 5.3 真实容量与限制

2026-09-17 审计时，生产媒体为 87 个文件、4,220,164,447 字节；最新迁移恢复包约 4.26 GB。跳板机可用空间约 73 GB，足够建立当前异机基线。该机制随“发生数据迁移的发布”触发，不等于持续媒体备份；阶段 3 必须继续实现周期增量异机复制、容量告警、保留规则和定期恢复演练。

真实演练已把 `release-lyzijF` 复制到异机：首次返回 `OFFSITE_BUNDLE_VERIFIED`，第二次返回 `OFFSITE_BUNDLE_CURRENT`；回执记录 87 个文件和 4,220,164,447 字节。迁移回执的候选提交与 P1-A21 生产提交一致，恢复包源提交与异机回执一致，三个摘要字段齐全，临时传输目录为 0。异机完成后仍有约 69 GB 可用空间。
