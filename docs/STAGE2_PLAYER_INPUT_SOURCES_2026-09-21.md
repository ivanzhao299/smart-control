## 1. 本批目标

`PlayerConsole.vue` 在欢迎页编辑用例拆分后，仍直接承担输入源识别、LED/投影显示链路恢复、欢迎方案修订发布和园区运营大屏翻页控制。这些动作跨越设备、播放和配置三个服务，页面或登录身份在异步请求中途变化时，页面内实现容易提交过期结果。

本批把完整输入源旅程提取到 `usePlayerInputSources.ts`，并把输入源识别、提示和欢迎方案下拉回显提取为纯函数。父组件只提供当前通道、播放列表、身份守卫和播放端口，不再直接调用 LED、投影、欢迎方案或运营大屏服务。

## 2. 收敛后的责任边界

纯投影模块负责：

- 依据播放通道权威媒体 ID 与名称识别播放内容、园区运营大屏、动态欢迎页和静态欢迎页；
- 生成输入源说明和欢迎方案下拉回显值；
- 集中维护三类内置素材的稳定名称。

组合式用例统一负责：

- LED 诺瓦控制器切回视频输入、投影仪恢复 HDMI，并保留“设备未确认只告警、不阻断已请求投放”的现场容错语义；
- 播放内容、动态/静态欢迎页和园区运营大屏投放；
- 欢迎方案管理员校验、修订号发布、权威回读、冲突刷新和下拉回滚；
- 园区运营大屏上一页、下一页、自动轮播和强制刷新；
- 页面/身份切换后的异步结果失效，以及强制刷新 3 秒冷却计时器的卸载清理。

`PlayerConsole.vue` 从 1922 行降至 1743 行。页面仍负责播放器、列表、电源、上传和模板布局，后续阶段 2 将继续按用例拆分。

## 3. 防回归契约

播放器输入源测试由源代码片段断言升级为可执行用例测试，覆盖：

1. 四类输入源和欢迎方案选择值只由权威播放状态派生；
2. LED 显示链路切换期间发生身份或页面变化，不再继续投放或显示成功；
3. 投影仪投放只恢复 HDMI，不误发 LED 输入指令；
4. 显示控制器未确认时显示告警，但按原语义继续请求内容投放；
5. 欢迎方案发布携带当前修订号，完成权威回读后再投放，冲突时刷新并回滚选择器；
6. 园区运营大屏命令只提交服务端确认状态，刷新冷却可在页面卸载时清理；
7. 结构门禁禁止输入源和运营大屏服务实现重新回流到 `PlayerConsole.vue`。
