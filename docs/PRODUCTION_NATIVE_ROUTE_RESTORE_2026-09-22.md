# 原生 App 生产远程入口恢复记录

日期：2026-09-22

## 事故与根因

- 2026-09-21 11:14，提交 `632b81a` 把原生 App 的远程地址误改为浏览器 PWA
  入口 `park.cnjinhu.com`。该入口的用途是为浏览器相机提供 HTTPS 安全上下文，
  不是原生 App 的生产服务器配置。
- 11:32，提交 `3e26ff1` 已把默认地址恢复到 `erp.cnjinhu.top`，但公网 DNS 仍指向
  北京主机 `123.57.220.65`。该主机从公网访问时 TLS 握手被直接重置。
- 原生 App 历史值带 `:8443`；新加坡边缘机虽已监听 8443，但公网安全组只放行
  标准 HTTPS 443，导致地址恢复后仍无法连接。
- 客户端此前只迁移“远程地址”栏中的 `park`，没有处理“现场地址”栏误填，
  写入时也允许错误地址再次保存。

## 修复

1. `erp.cnjinhu.top` A 记录从 `123.57.220.65` 切换到新加坡边缘机
   `47.236.122.224`。
2. 公网入口统一为 `https://erp.cnjinhu.top/control/`（HTTPS 443）。边缘机继续通过
   北京跳板机和 WireGuard 访问同一台 GK9000，业务数据源未改变。
3. iOS 2.1.8 和 Android 1.1.17 同时迁移以下旧保存值：
   - `park.cnjinhu.com` 出现在现场或远程地址栏；
   - `erp.cnjinhu.top:8443` 出现在远程地址栏。
4. 现场地址、远程地址在读取和保存时都会规范化；iOS 保存后立即使用规范化结果，
   不需要重启 App。
5. CI 地址门禁同步检查两端默认地址、两类缓存迁移和 iOS 当前会话切换逻辑。

## 验证基线

- 阿里云权威 DNS `dns29.hichina.com`、`dns30.hichina.com` 均返回
  `47.236.122.224`。
- 对新地址进行可信证书校验，`/control/` 返回 HTTP 200。
- `/api/client-auth/ping` 返回 `ok=true`、`service=client-auth`。
- 新加坡边缘机 nginx 配置检查通过，HTTP 入口重定向到标准 HTTPS 443。
- iOS 配置源通过 Swift 类型检查；Android 与 iOS 正式构建由 PR 和主分支 CI 完成。

## 数据安全

本次没有执行数据库迁移、数据写入或账号变更。公网流量仍到达原 GK9000 后端，
只更换 TLS 边缘入口并规范化客户端地址。
