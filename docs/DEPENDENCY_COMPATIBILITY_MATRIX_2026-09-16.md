# 生产依赖兼容与安全升级矩阵（2026-09-16）

## 1. 治理原则

1. 后端与前端分别升级、分别验证、分别部署，避免把两个运行时的兼容风险叠加。
2. 先删除未使用的依赖，再升级直接依赖，最后才使用精确版本覆盖解决上游尚未发布补丁的问题。
3. 每批必须通过锁文件冻结安装、生产依赖审计、全量测试、构建、空库迁移演练和生产部署验证。
4. CI 和生产发布在发现 `critical` 或 `high` 公告时失败；`moderate` 只能在记录调用路径、责任批次和处理期限后暂时保留。
5. 锁文件是安装版本的唯一依据。包清单只声明兼容范围，CI 与生产统一使用 pnpm 10.33.4 和 `--frozen-lockfile`。

### 结果

| 生产依赖数 | critical | high | moderate | low |
|---:|---:|---:|---:|---:|
| 291 | 0 | 0 | 1 | 0 |

唯一剩余公告为 `@nestjs/core@10.4.22` 的 SSE 字段注入问题，修复版本为 11.1.18 以上。当前仓库没有 `@Sse()` 或 `Sse()` 调用路径，无法从现有 HTTP/WebSocket 业务触发。该项不作为永久豁免：在 P0-C2 升级 Nest 核心主版本并重新验证全部模块。

### 本地证据

- `pnpm install --frozen-lockfile` 通过，锁文件不再包含 `sqlite3` 安装包。
- 后端 60 个测试套件、640 项测试全部通过。
- TypeScript/Nest 生产构建通过。
- 空白 SQLite 依次执行 26 个迁移，`migration:show` 全部为已执行，`PRAGMA integrity_check` 返回 `ok`，生成 40 张表。
