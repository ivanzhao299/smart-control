# 园区大屏布局编辑契约

本地候选，2026-09-17。没有执行生产部署、现场屏幕写入或 GK9000 重启。本批不新增数据库迁移；累计候选仍包含音响配置的第 41 个迁移。

## 接口与权威数据

- `GET /api/system-branding/park-ops` 保持公开只读，用于播放器和编辑器；返回 `config / revision / checksum / updatedAt`。仅合法空快照 `config:null, revision:0` 代表从未保存。
- 新编辑器只用 `PUT /api/system-branding/park-ops/editor`，请求必须包含对象 `config` 和非负安全整数 `expectedRevision`。运行时 DTO 拒绝缺失、字符串、布尔、负数、小数、不安全整数及额外信封字段；内部文档仍由现有有限大小/数量/取值校验器处理。
- 只允许已验证管理员。审计身份从服务端 actor 派生，不接受请求提供的用户名。布局的权威数据及不可变历史继续位于 `RuntimeConfigStore`，不另写 JSON 文件。
- 首次保存的 `expectedRevision:0` 必须进入数据库事务检查；不能只依靠服务实例内的队列。普通更新继续 CAS，冲突为 `409 / RUNTIME_CONFIG_REVISION_CONFLICT`，无变化不增版本或历史。
- 布局内容校验失败为 `400 / PARK_OPS_LAYOUT_INVALID`；已有 HTTP 异常保留原状态。

## 草稿与生命周期

1. 初始状态不可保存。成功取得合法快照才记录版本；读取失败不冒充空库、不重置草稿。
2. 保存克隆当前草稿并绑定该次版本，保存期间禁止重复提交和重新读取，但允许继续编辑。成功只替换未继续修改的草稿；有新输入时仅推进版本并提示新修改尚未保存。
3. 保存冲突、网络错误或返回结构异常后保留草稿并暂停后续写入。网络错误可能发生在服务端已经提交之后，因此必须重新读取核实，不盲重试。
4. “重新读取”必须确认会替换未保存草稿；取消不丢数据。读取期间继续编辑时也保留草稿，不把晚到快照覆盖上去。
5. 响应只可用于请求开始时的账户会话。换账号、换令牌或页面销毁后不应用晚到结果；旧请求的 401 不删除可能已被替换的凭据。
6. 普通显示页继续按原 15 秒周期读取布局，本批不改变播放控制、翻页、分辨率、3D 渲染策略或业务数据更新频率。校准页不后台轮询覆盖草稿。

## 兼容边界

旧 `PUT /api/system-branding/park-ops` 暂时保留原始文档及 `{config, expectedRevision}` 信封两种输入；同样验证管理员并记录真实身份。旧端无版本输入不能获知自己是否已过期，不能宣称完全防覆盖。

兼容桥退役评估日期为 2026-10-17（记录日期，不是自动停用任务）。先盘点 PWA/静态页缓存与现场版本，确认旧端已退出，才可另行移除。品牌名称、Logo、欢迎页配置是独立未完成域，不能以布局契约完成代替它们的验收。

发布时后端必须先具备新 editor 路由，再激活新前端；不能将本候选当成仅前端更新发布到旧后端。新旧静态脚本使用不同版本 URL，新页面先加载状态模块再加载校准器，旧页面仍可访问兼容端点。
