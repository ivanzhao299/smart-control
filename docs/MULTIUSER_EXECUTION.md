## 资源模型阶段进展

已增加媒体/播放历史 owner_user_id 外键及索引、媒体 visibility/source、用户默认 10GiB 配额字段、通道 initiator_user_id。迁移保留原始文件路径及ID，历史资料 shared/legacy，新资料默认 private/upload。回退在出现新资料、归属历史或播放上下文时拒绝丢弃字段，要求维护模式下保全资料并恢复上线前快照。

真实 SQLite 迁移上/下、路径及历史保留、外键删除保护、私人和新增公共资料回退拦截均通过。统一资源权限策略覆盖他人资料读写/推送拒绝、公共资源仅管理员编辑、只读/legacy 写入拒绝、无主私有文件拒绝公开。累计本阶段相关 13 测试通过，后端编译通过。测试使用内存库，未连接生产库。

注意：配额目前只有字段；资源策略尚未接到所有业务入口。个人播放列表结构、审计、配额原子预留、安全文件、设备身份和前端仍待实施。迁移只有在整条权限链完成且部署前备份后才能执行。下一步在 MediaService/MediaController 所有入口传递 Actor 并接入策略，处理系统内置素材的显式 shared/system 归属，然后改个人播放列表与播放器身份。

本地测试必须将 /opt/homebrew/opt/node@20/bin 放到 PATH 首位；仅使用该目录的 corepack 可让子进程仍采用系统 Node 24。已用 Node 20 rebuild better-sqlite3，SQLite 测试通过。

普通用户管理自己的资料和列表，查看并投放公共资料；管理员管理全部内容；只读用户不能写入或控制设备。历史资料迁移为系统公共资料，不移动原文件。设备为共享实体，后推送覆盖前推送，但其他用户只看到占用状态，不获得私人文件地址或名称。网盘授权暂为管理员能力，避免共享授权暴露目录。用户停用保留资料，删除账户优先采用停用方式，避免产生无主资料。

## 验收边界

媒体文件、缩略图、文档副本、播放历史、播放通道和 WebSocket 必须一起隔离。媒体查询结果不暴露服务器绝对路径。内部播放器身份不得拥有用户管理权限。登录身份以验证后的服务端信息为准，不相信请求体 ownerUserId。阶段代码不得提前发布为已完成的隔离版本。
