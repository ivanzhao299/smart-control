# 阶段 2：音频播放列表与播放会话用例收敛

> 日期：2026-09-21
>
> 范围：P2-A18
>
> 结论：背景音乐播放列表持久化、媒体选择器回跳、后台播放会话同步、播放控制和视觉进度已从 `AudioPage` 收敛到单一组合式用例；清空失败时不再显示与后台不一致的假空列表。

## 1. 问题与修正

旧 `AudioPage` 同时维护播放列表 CRUD、媒体选择器回跳、播放模式、后台 slot 3 会话同步、浏览器时长探测和视觉进度。页面既持有界面状态又编排持久化与播放端口，导致职责过重，也使失败恢复只能通过页面源码间接验证。

本批新增 `frontend/src/composables/useAudioPlaylist.ts`，统一负责：

1. 后台播放列表投影、媒体库候选项和添加、移除、改名、清空。
2. 播放、停止、暂停、恢复、上一首、下一首和播放模式保存。
3. 媒体选择器路由回跳的幂等持久化。
4. slot 3 当前媒体、播放会话、暂停态和播放模式的同步。
5. VBR 时长探测竞态保护、视觉进度启动、暂停、恢复与页面停用清理。

`AudioPage` 从 2029 行降为 1788 行，只保留页面组合、设备矩阵和其他尚未拆分的职责。

## 2. 权威来源与失败恢复

- 后台 slot 3 通道继续是当前媒体、播放会话、暂停态和播放模式的唯一事实来源。
- 播放列表每次持久化后重新读取后台投影，不建立浏览器本地副本。
- 改名采用乐观显示；请求失败恢复原名称。
- 播放模式保存失败恢复后台最后确认的模式。
- 清空列表逐项删除并保留审计粒度；任何一项失败都会重新读取后台列表，界面不再无条件清空。
- 如果删除与后台重读同时失败，界面保留现有投影并提示稍后刷新，不谎报“已重新读取”。
- 时长探测完成时必须同时匹配媒体 ID 和播放会话，旧结果不能越过新会话。
- 媒体选择器重复回跳视为幂等，不重复写入播放列表。

## 3. 数据与发布边界

- 无数据库迁移，不改写媒体文件、设备配置或协议。
- API、路由、slot 3 定义、播放后端推进逻辑、模板和样式保持不变。
- 自动测试通过注入播放端口、API、消息和确认框运行，不连接现场设备。
- 生产差异分类为 `frontendCode=true`、`backendCode=false`、`releaseControl=false`、`highRisk=false`、`scope=frontend`。
