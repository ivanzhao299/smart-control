## 1. 目标与不可突破的约束

目标是把项目从“功能可用、依赖现场经验维护”提升为“数据来源清晰、变更可验证、部署可追踪、故障可恢复”的 5/5 工程状态。

全过程遵守以下约束：

1. 生产 SQLite、运行时 JSON、媒体文件、日志和设备配置先备份、后迁移；任何失败不得用旧代码覆盖新数据。
2. 数据结构只通过可重复、可审计的版本化迁移前进；禁止服务启动时临时执行 DDL 自愈。
3. 每个配置域只允许一个权威写入源；兼容读取只能作为有期限的迁移桥梁。
4. 每阶段独立交付，必须通过自动测试、构建、备份校验、迁移演练和生产健康检查后才能进入下一阶段。
5. 发布必须绑定准确提交号；生产验证失败时停止继续变更，保留现场数据并使用前向修复。
6. 高风险改造先建立回归测试和观测指标，再替换实现；禁止一次性重写关键模块。

## 4. 阶段 1：数据可靠性与版本统一

1. [x] 建立数据资产表：SQLite 表、运行时 JSON、媒体目录、缓存、日志、密钥分别标明权威源、备份和恢复方法。
2. 建立 SQLite 统一 `RuntimeConfigStore`，以数据库事务锁提供原子写入、修订号、SHA-256 校验、历史快照、审计来源和并发冲突检测；避免再形成一套长期文件数据库。
3. 把视频绑定、园区运营内容、系统品牌、场景动作等 JSON 配置逐域迁移到统一存储接口。
4. NVR 与摄像头通道只保留视频绑定配置一个权威源；摄像头拉流服务通过该服务解析通道，移除重复硬编码。
5. 统一生产数据库路径和启动检查，所有环境输出相同的数据库版本、迁移版本和数据目录摘要。
6. [x] 将认证、系统品牌、播放和百度网盘服务中的启动 DDL 移除，由现有 TypeORM 迁移和只读启动门禁负责。
7. 在生产数据副本上执行升级、重复执行、故障中断和恢复演练，记录校验和与行数对账。

退出条件：不存在双写和无期限兼容源；生产启动不执行临时 DDL；备份恢复演练能在目标时间内完成且数据对账一致。

## 5. 阶段 2：代码结构与 API 收敛

1. 以行为边界拆分 `AudioPage`、`HvacPage`、`MediaPage`、`PlayerConsole`、`MainLayout` 和 `media.service`，先提取无状态逻辑，再拆组件和服务。
2. 所有配置接口统一 DTO、权限、错误码、审计字段和并发版本；关键 API 生成稳定契约。
3. Vue 路由、导航、权限和预取由同一元数据表生成，移除重复映射。
4. 建立关键用户旅程测试：登录、灯光、大屏投放、拍照上屏、媒体上传、视频绑定和检测范围保存。
5. 明确模块依赖方向，禁止页面直接拼接跨域 API 和服务直接访问其他域的内部存储。

退出条件：关键模块具有清晰责任边界；关键用户旅程有自动化保护；配置 API 行为一致且可追踪。

## 6. 阶段 3：发布与可观测性

1. CI 生成带提交号、依赖清单和校验和的后端、前端不可变制品，生产只安装已验证制品。
2. 部署流程分为预检、数据快照、迁移、制品切换、健康验证和完成六个可恢复状态。
3. 代码目录只读，数据库、JSON、媒体和日志全部位于独立数据盘目录；备份不与源数据共盘保存唯一副本。
4. 建立请求、设备控制、数据库、媒体存储、HLS、WebSocket 和部署指标；日志统一关联请求号、用户、设备和发布版本。
5. 告警必须对应可执行处置手册，覆盖磁盘容量、数据库失败、配置写入冲突、服务重启循环和设备离线。

退出条件：任一生产实例都能回答“运行哪个制品、使用哪个数据库版本、数据在哪里、最近一次迁移和备份是否成功”。

## 7. 5/5 验收评分标准

| 维度 | 5/5 证据 |
|---|---|
| 数据可靠性 | 单一权威源、版本化迁移、校验备份、定期恢复演练、无启动 DDL |
| 安全 | 无仓库私钥和硬编码凭据、最小权限、敏感字段脱敏、依赖风险受控 |
| 测试与门禁 | 前后端测试覆盖关键旅程，CI 与生产验证一致，失败阻断发布 |
| 架构与维护 | 模块边界清晰、无超大职责文件、接口契约和依赖方向稳定 |
| 发布 | 不可变制品、提交号一致、数据与代码分离、可恢复的发布状态机 |
| 可观测性 | 指标、结构化日志、审计和告警可定位到版本、请求、用户与设备 |
| 文档与运维 | 架构、数据字典、迁移、备份恢复、发布和故障处置文档经过演练 |

只有全部维度都有自动化或演练证据时才记为 5/5；完成代码修改但没有运行证据的项目不计满分。
