# 媒体模块职责边界

更新：2026-09-17。当前为本地候选实现，尚未部署。

## 已分离的职责

| 模块 | 负责 | 不负责 |
|---|---|---|
| `MediaService` | 目录查询、调用方授权、入库协调、资料操作锁、目录元数据事务；保留原有公共方法 | 不再执行 FFmpeg/FFprobe 进程、解释下载 Range 或重复定义扩展名策略 |
| `media-file-policy` | MIME/扩展名分类、文件名规范化、孤立文件类型提示 | 不读写文件、数据库、环境变量或用户身份 |
| `media-byte-stream` | 校验路径与已打开文件描述符、文件字节读取、Range/416/PDF 变体 | 不查数据库、不决定哪个账号可读；调用方须先选定获授权资料 |
| `MediaVideoProcessor` | 视频准备状态、转码协调、容量预留、原文件与衍生文件记账、失败清理 | 不导入目录服务、控制器或其他业务域；通过明确回调共享操作锁和字段更新 |
| `FfmpegMediaTools` | 探测工具、读取编码信息、调用有容量上限的转码输出器 | 不访问目录数据库、用户凭据或现场设备 |

处理器与主服务共用同一资料操作锁。重复准备同一视频不启动第二次探测；未退出的探测不能提前释放操作锁。数据库字段只按原有最小字段集合更新，不能把异步操作前读取的旧所有者、可见性或文件别名写回。

## 保持的安全和兼容规则

- `MediaService.prepareVideo`、`openStream`、`classifyKind` 和工具状态接口不变，不改控制器权限或 URL。
- FFmpeg/FFprobe 保留环境变量覆盖和 GK9000 的既有 Windows 默认安装路径；参数数组直接交给进程，不经过 shell。
- 转码保留原文件；原文件名为 `playback.mp4` 时使用不同的衍生文件名。临时输出独占创建、有容量上限；失败只清理本次产生的临时文件。原有播放副本和未记账的恢复证据不随失败删除。
- 预留只在安全清理/记账完成后释放；进程中断或记账失败仍走现有离线恢复流程，不新增自动恢复写入。
- 下载仍通过 realpath、设备号/inode、已打开描述符和实际文件长度检查，保留分段/空文件/416行为；不因模块拆分放宽媒体根目录限制。
- MIME 优先级与扩展名后备保持一致，文件名规范化不改变已存文件。

## 新增的探测资源上限

- 工具状态检查：15 秒。
- 视频元数据探测：60 秒。
- 探测标准输出最多 2,000,000 字节，标准错误只保留最后 8,000 字节；错误消息最多附带其中最后 2,000 字符。
- 超时或输出超限会终止该探测子进程，并等待进程关闭后返回失败。**这些是探测限制，不是大型视频完整转码的时间上限**；转码仍使用原有容量预算和流式背压。

## 自动化证据

- 文件策略 18 项：MIME 优先级、音频/文档/视频/图片扩展名、大小写、未知类型、文件名边界及注册表不受返回值修改影响。
- 工具 10 项：参数不经 shell、编码解析、工具缺失、Windows 默认路径分支、15/60 秒探测期限、输出上限、失败诊断和容量写入器委托。
- 依赖边界 5 项：四个新模块的依赖白名单，以及目录服务不能重新引入子进程/Range/扩展名实现。该门禁覆盖本次新边界，不代表全仓依赖审计完成。
- 原有实际 SQLite 入库补偿、所有权竞争、删除/转码互斥与文件描述符下载测试继续通过；新增重复准备与共享锁测试。
- 在本机真实 FFmpeg/FFprobe 上生成合成视频，确认转为 H.264、原文件字节不变、双文件容量记账、超额失败后原文件和既有播放副本均保留；未用生产媒体作测试。
