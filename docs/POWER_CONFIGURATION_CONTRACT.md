# 电源回路配置契约

2026-09-17 本地候选；没有部署生产、改写现场配置或发送现场设备命令。本批对应阶段 2 的 C05 电源部分，品牌字典尚待收口。

## 配置与物理控制分离

| 入口 | 责任与权限 |
|---|---|
| `GET /api/power-circuits/configuration`、`/:id` | 仅管理员读取关系表元数据；包括禁用回路，不读取硬件，不返回虚构通断状态。 |
| `POST /api/power-circuits/configuration` | 运行时创建 DTO；初始修订 1，可信管理员、写入和审计同一事务。 |
| `PUT /api/power-circuits/configuration/:id` | 更新 DTO 必带正安全整数 `expectedRevision`；仅写变化字段。 |
| `DELETE /api/power-circuits/configuration/:id?expectedRevision=N` | 必须匹配已读版本；删除配置不发送断电指令。 |
| 既有 `/power-circuits` 读数与 `/:id/on`、`/:id/off`、`/sequencer/all-on`、`/sequencer/all-off` | 保留原控制/读数行为与权限，不混入配置编辑验收。 |

后台改用纯配置接口，原实时“状态”列改为配置版本；实时通断状态仍在电源控制页显示。启用/停用配置改变后续目录可见性，不代表设备已通/断电。界面不再提示“没填继电器就不会操作真硬件”这一过度保证，实际控制路由取决于适配器及网关配置。

原 create/update/rename/delete 入口仍作为旧客户端桥梁：补运行时 DTO 和真实 actor；持久化也经过同一事务、递增版本并审计。旧 create/update/rename 的完整回执仍可能等待遥测；新客户端一律不用它们保存元数据。旧端允许缺省版本，无法保证拒绝自身陈旧覆盖；在 2026-10-17 评估缓存及客户端覆盖后再决定退役，不自动停用。

## 数据约束与审计

- `power_circuit` 仍是唯一权威表；新迁移 `AddPowerConfigRevision1789700000000`（完整链第 42 项）仅新增 `config_revision INTEGER NOT NULL DEFAULT 1`，不重排回路、不修改接线、名称、额定值或启用状态。
- 所有输入字段白名单；禁止 `reading`、`configRevision`、`actor` 等只读/伪造字段。版本不接受数字字符串；查询参数版本由明确 DTO 转换。可空的接线地址、图标和备注继续允许 null；false 与 0 不被当成“未填”。
- 文本长度、整数及范围参照原实体和编辑控件：relay 1–32、Modbus 地址 1–247、电压 0–600、电流 0–200、功率 0–100000、排序 0–9999。既有超范围字段不会被迁移自动修正；新提交须满足约束，历史自定义 category 字符串仍可保留。
- SQLite 串行事务中重查命名管理员仍启用且有管理权限。CAS 更新/删除与 `audit_logs` before/after 快照原子提交；无变化不增加版本或审计，审计失败回滚配置。没有硬件等待发生在此事务内。
- 领域错误：陈旧版本 `409 / POWER_CONFIG_REVISION_CONFLICT`，编码占用 `409 / POWER_CONFIG_KEY_CONFLICT`，不存在 `404 / POWER_CONFIG_NOT_FOUND`，服务级字段校验 `400 / POWER_CONFIG_INVALID`；HTTP DTO 的非法输入由统一验证管线返回 400。匿名 401、非管理员 403。
- 配置提交后使原遥测缓存失效；新配置保存本身不触发采样。现有物理开关失败不报成功、断路器目标匹配与读数缓存回归保持通过。

## 编辑器行为

- 配置读取直达新入口，不使用实时读数缓存。读失败禁止新建及修改；已有草稿保留。
- 保存克隆草稿并冻结版本，禁止重复提交；返回后保留保存期间的新输入。新建成功但继续编辑时转为该记录的新版本，不重复新建。
- 冲突或网络不确定结果暂停保存，必须确认重新读取；取消确认不丢草稿。读取期间的新编辑也不被晚到结果替换。
- 删除确认绑定原记录及原版本。切换账户、服务地址或销毁页面后旧响应/确认不得继续修改新页面。
- PWA 行内改名先读管理员元数据，冻结版本，仅合并元数据，保留当前电流/电压/开关读数。失败保留可见草稿并提供确认重读；取消/切页后忽略晚到响应。迟到的实时读数可以更新遥测，但不能降低配置版本或覆盖新名称。
