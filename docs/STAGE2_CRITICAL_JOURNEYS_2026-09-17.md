## 1. 问题结论

### iPhone 相机

页内相机依赖浏览器 `getUserMedia`，只能在 HTTPS 安全上下文使用。从 HTTP 局域网地址打开或安装的 PWA 会被 iOS 浏览器直接阻止，页面代码无法绕过。生产规范入口为 `https://park.cnjinhu.com/control/`；首次从旧 HTTP PWA 迁移时需要在 HTTPS 入口重新登录并重新添加到主屏幕。

本批保留已经验证过的 `getUserMedia + canvas` 拍照链路，不恢复曾导致 iOS PWA 闪退的 `<input capture>` 系统相机路径。非安全上下文和浏览器能力不足现在分别给出明确提示。

### 视频检测范围

原编辑器发出保存事件后立即关闭。API 失败、网络中断或服务端保存与客户端状态不一致时，刚绘制的检测线和 ROI 会从界面消失，造成“数据又丢失”的感受。与此同时，编辑器没有携带 SQLite 配置修订号，两个旧页面可能相互覆盖。

现在编辑器等待保存完成，并重新读取服务端配置核对 AI 开关、检测线和 ROI。只有完全一致才关闭；请求失败、409 并发冲突或回读不一致都保留当前画布。后端以 `expectedRevision` 检查当前修订，冲突返回稳定错误码 `VIDEO_BINDING_REVISION_CONFLICT`。该字段对旧 PWA 可选，以支持安全滚动升级。

## 2. 拍照上屏数据边界

发布顺序固定为：

1. 读取当前欢迎照片绑定。
2. 上传新的 LED 适配照片。
3. 将欢迎页绑定切换到新媒体记录。
4. 尝试让大屏切换到欢迎页。
5. 对旧媒体执行可恢复删除。

如果第 3 步失败，只回收本次新上传，旧绑定与旧照片保持不变。第 4 或第 5 步失败不会撤销已经确认的新绑定。生产媒体记录仍以 SQLite `media_assets` 为权威源，照片文件保存在数据盘 `D:\Media\welcome-photos`。
