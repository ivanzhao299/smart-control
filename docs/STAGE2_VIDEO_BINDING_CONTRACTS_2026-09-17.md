> 结论：已发布并完成生产数据不变性、双代 PWA 资源与公网 HTTPS 验收；阶段 2 继续进行大模块拆分。

## 1. 视频绑定的单一写入契约

NVR、摄像头通道、删除、显示布局、AI 全局开关和单路检测几何现在都进入 `VideoBindingService` 的同一串行变更边界。新管理端的所有持久化写入都携带当前 `expectedRevision`；过期修订不会覆盖新值，统一返回 HTTP 409、`VIDEO_BINDING_REVISION_CONFLICT`、预期修订和当前修订。

DTO 中的 `expectedRevision` 在滚动升级期可选，因此旧 PWA 不会因后端先发布而立即失效。新 PWA 已全量提交修订，409 时重新读取最新配置并保留当前表单，由管理员核对后再保存。

## 2. 错误、审计与修订收敛

- 缺失 NVR 或通道返回稳定 404，非法引用和重复标识返回稳定 400。
- 全局异常过滤器只传递经审查的大写机器码与修订数字，不回显任意异常载荷，避免把令牌、密钥或内部对象意外发给客户端。
- 修订历史记录命名管理员和稳定 API 来源，取代笼统的 `admin-api`。
- 写入后文档与当前文档完全相同时，直接返回当前值，不新增历史修订。

## 3. 管理员会话竞态

真实浏览器验收暴露了一个独立但同级的可靠性问题：刷新控制页时，命名管理员 bearer 和旧兼容客户端令牌会并发恢复。后恢复的身份会主动作废旧请求，但旧检查把 `AbortError` 当作凭据无效，删除了刚恢复的管理员会话。

修复后，管理员 store 每次检查前重新同步 HTTP bearer，相同令牌的并发检查去重，身份边界主动中止重试一次。断网与主动中止保留凭据，只有权威 401/403 才清除；请求完成前令牌已更换时，旧请求不再改写新会话。
