# 音响配置版本编辑契约

更新：2026-09-17。当前为本地候选，尚未部署。此文档不是生产变更授权。

## 权威数据与迁移

- 输出、输入和预设仍分别以 `audio_output_zone`、`audio_input_source`、`audio_scene` 为唯一来源，没有增加 JSON 副本或另一个运行配置文档。
- 第 41 个迁移 `AddAudioConfigRevisions1789690000000` 为这三张表增加 `config_revision INTEGER NOT NULL DEFAULT 1`，API 字段为 `configRevision`。原有每个字段保持不变；不修改 `audio_desired_link`。
- 配置修订不等于设备状态修订。输入实时 `desired_gain_db`/`desired_muted` 更新不增加配置修订，只更新自身字段；音量控制和设备捕获与配置写入使用同一 SQLite 事务协调队列，不在等硬件回复时占用配置事务。
- 启动只读门禁要求新迁移和三列存在，不做启动 DDL。迁移发现已有但不兼容的列定义或无效修订值会失败关闭。禁止直接降级删除修订列；需要配套归档和明确恢复授权。

## API

| 路径 | 请求/响应 | 规则 |
|---|---|---|
| `GET /audio-config/zones|inputs|scenes` | 原列表行增加 `configRevision` | 既有读取访问策略和 `includeDisabled` 保持不变 |
| `POST /audio-config/zones|inputs|scenes` | 白名单 DTO；创建不能带已有修订号 | 输出/输入需 channel，场景需 presetNum；初始修订 1 |
| `PUT /audio-config/{domain}/{id}` | DTO 加 `expectedRevision` | 在同一事务核对版本、最小字段更新、增加修订并记审计；无变化不增修订/审计 |
| `DELETE /audio-config/{domain}/{id}?expectedRevision=N` | 查询修订号 | 同一事务核对、删除和保留删除前审计快照 |
| `POST /audio/scene/apply/{preset}` | 可携带 `expectedRevision` | 携带时核对预设快照；不一致或记录已删除返回 409，不调用设备。通过后执行已核对的那份内容 |

九个配置写入入口继续要求管理员。控制器从服务端身份取得操作者，服务事务再次验证命名账号启用且仍为管理员。不能通过 DTO 自填操作者或修订列。

校验：通道为整数 0–7，预设为整数 1–12，名称不全为空且最长 64，楼层/颜色最长 16，提示最长 128，排序有界；场景至多 8 路、输出不重复、输入编号不重复且最多 8 个，音量为整数 0–100、静音为布尔值。可空字段允许显式 null，其他字段不把 null、字符串数字或字符串布尔值强制转成有效值。非法路由不再静默丢弃或钳制成另一份配置。

领域错误：过期修订 `AUDIO_CONFIG_REVISION_CONFLICT`（409）、占用的通道/预设 `AUDIO_CONFIG_KEY_CONFLICT`（409）、不存在记录 `AUDIO_CONFIG_NOT_FOUND`（404）、服务层无效参数 `AUDIO_CONFIG_INVALID`（400）。DTO 验证沿用全局 400 校验消息；认证/权限沿用 401/403。客户端遇到冲突不自动重试覆盖。

## 立体声与审计

- 通道 0/1、2/3 的命名约定不变，改任一侧名称时同事务维护配对名称；两侧有实际变化时各自增加修订并产生审计。
- 输出保存响应可附 `pairedZone`，用于显示服务器确认的另一侧名称和版本，不持久化到实体。PWA 就地改名只发一次请求，不再靠第二次请求同步另一侧。
- `audit_logs` 使用三张实体表名作为类型，记录命名操作者、变更前后和 `audio-config:catalog-write|catalog-delete` 来源。管理审计页可按这些类型筛选；没有开放新的自动回滚入口。
- 第二侧审计失败会回滚第一侧已写入的数据/审计，不能出现“改名成功但无审计”的半提交。

## 编辑器与失败行为

- 后台载入和显式刷新直读服务器，不使用显示页的 30 秒缓存；表单复制服务器对象，不直接编辑共享缓存。
- 读取失败/缺少版本时禁用保存，旧草稿保留。409 保留草稿并暂停保存；刷新需明确确认可能丢弃草稿，不能自动覆盖重试。
- 保存期间同一编辑器不同时发第二条写请求；用户在请求期间新输入的字段保留。保存一行不刷新并抹掉其他行草稿；联动声道若有未保存草稿也保留并提示重载。
- 场景路由编辑保存未显示的禁用输出内容，不会因编辑器只画启用输出而删除隐藏路由。
- “下发试听”先保存，再携带返回修订发控制请求；保存失败、版本冲突、换账号、页面销毁或保存期间关闭对话框时，不继续下发。已经到服务器的设备命令不能承诺撤销。设备返回未确认时不显示试听成功。
- 普通 PWA 就地改名先读最新名称/版本，不重置音量/静音；失败保留原显示名称，重新编辑时重新核对版本。

## 滚动兼容退出

后端暂接受旧客户端不带 `expectedRevision` 的既有更新/删除；这些操作也增加修订和审计，但不能保护旧客户端自身的陈旧草稿。不能据此宣称跨所有旧客户端完全防覆盖。当前新版前端所有配置写入都带版本，未取得有效版本时拒绝发送；新后台必须先于新前端部署。

- 全新库完成 41 个迁移；历史迁移链副本逐字段对账、重复运行、中途失败回滚和配套备份恢复通过。证据是本机合成库，不是生产数据副本。
- 真实 Chrome + 完整构建 + 临时 Mock 后端覆盖管理员保存、另一管理员更新、409 草稿保留、明确重载、读取失败禁用保存，以及真实 HTTP 的 400/401/403 和过期试听 409。
- 正式发布前仍须取得新维护授权，对现场数据库进行配套备份、离线副本升级/对账和恢复校验，再执行迁移、后端/前端发布、运行 SHA 与物理现场验收。不得把本机测试当作现场音频听感、延时或生产恢复证据。
