# 阶段 2：空调页纯视图模型边界

> 日期：2026-09-21  
> 范围：P2-A9  
> 结论：首批无状态展示与选择逻辑已从空调页面拆出并发布生产；页面继续负责轮询、设备命令和配置持久化，避免在同一批次改变现场控制时序。

## 1. 变更动机

`HvacPage.vue` 同时维护设备状态、楼层筛选、分组投影、汇总、选择集合、命令编排和配置编辑。原实现把可纯计算的展示逻辑夹在现场控制流程之间，任何展示调整都需要在大页面中理解设备命令副作用，不利于独立回归和后续组件拆分。

本批次建立 `frontend/src/features/hvac-view-model.ts`，集中负责：

- 内机和分区的楼层投影；
- 保留空分区、生成未分组分区和稳定排序；
- 在线、运行、故障、目标温度和模式摘要；
- 分区卡的已知/未知状态映射；
- 多选、取消和当前楼层反选；
- 仅在状态一致且已知时提供批量控制初始值。

`HvacPage.vue` 继续负责轮询、加载状态、API 调用、设备下发、分区维护和用户提示。模板、样式、API 地址、设备命令参数与发送顺序均未改变。

## 2. 数据与发布边界

- 无数据库迁移，不读取或写入生产配置，不发送设备命令。
- 发布范围分类为 `frontendCode=true`、`backendCode=false`、`highRisk=false`、`scope=frontend`。
- 后端发布验证被跳过，部署明确执行“frontend code only”，不构建或重启后端。
- 数据库只读检查返回 `MIGRATIONS_CURRENT`；无需备份或迁移隔离环境。
- 生产构建旁路生成后原子切换，保留上一代 45 个 PWA 兼容资源。

## 3. 自动验证

新增 6 项纯模型回归，覆盖：

1. 楼层筛选、稳定顺序和空分区保留；
2. 未分组内机生成和空数据边界；
3. 汇总与分区卡对未知状态的处理；
4. 目标温度、模式和风速只接受一致的已知状态；
5. 当前楼层反选不改动隐藏楼层的选择；
6. 页面必须消费共享模型，禁止同一批投影逻辑回流。
