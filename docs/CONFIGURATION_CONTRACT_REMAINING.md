# 阶段 2 配置契约收口清单

2026-09-17 本地工作清单。来自当前控制器、DTO 与服务实现的盘点，不是生产权限扫描，也不是新增生产操作授权。按配置域逐项关闭，避免只依据类名带 `Dto` 或测试通过就宣称全部完成。

## 统一退出证据

每个域必须核对：运行时输入校验；认证及管理员授权；一致、可区分的失败响应；可信操作人；写入与审计的原子性；并发版本；无变化行为；旧客户端兼容退出办法；前端草稿/会话生命周期；真实本地 API 旅程。涉及物理设备的配置，先保存并验证配置，再由明确授权的现场验收确认硬件效果。

权限需要同时检查全局 `GlobalAuthGuard`、控制器类级守卫和方法级守卫。方法没有单独 `UseGuards` 不代表接口无保护；存在 TypeScript interface 或 `Partial<...>` 也不代表服务端完全没有手工校验。以下“待收口”仅指尚未完成统一退出证据。

## 仍独立存在的阶段门槛

- 大职责页面/服务拆分与依赖方向保护，不能被配置契约测试代替。
- 新候选生产发布、准确版本身份、现场用户行为验收。
- 阶段 3 的不可变制品、发布状态机、数据路径与可观测性。
- 阶段 4 的授权灾备/升级演练、安全复审及运维手册验收。
- 自托管构建机按用户要求暂停，不是本清单的前置条件。
