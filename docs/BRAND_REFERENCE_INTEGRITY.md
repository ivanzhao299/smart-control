# 品牌目录与设备、驱动引用一致性

2026-09-17，本地候选，C05 的关联完整性子批次；不是品牌配置全部契约关闭，也不是生产验收。

2026-09-18 续批已完成品牌 DTO/CAS/原子审计和编辑器本地验证，并将硬件审计回滚纳入引用事务；当前状态见 [品牌配置契约](./BRAND_CONFIGURATION_CONTRACT.md)。下文保留上一批边界记录，不代表新增契约仍未实现。

## 问题与本批处理

`brands.name` 与 `hardware_units.vendor`、`driver_templates.vendor` 是精确字符串软关联，没有外键。此前服务端允许单独修改品牌标识，导致原引用脱钩；品牌自动建档和引用记录保存是两次独立写入，后续失败会留下多余目录行。品牌删除的引用计数与实际删除也不在同一事务。

- `BrandsService.withReference` 在同一 SQLite 事务中建立缺失品牌、保存引用记录。硬件创建/更新、自定义驱动创建均使用传入的事务 manager；引用保存失败、唯一键检查失败、驱动参数序列化失败时一起回滚。
- 品牌新增/修改/删除，以及硬件和自定义驱动删除，使用同一个 DataSource 事务队列。硬件更新在事务内重新读当前行，排队的局部编辑不会把先前 vendor 带回。
- 被任何设备或驱动引用的品牌，改标识及删除返回 `409 BRAND_REFERENCED`，附设备和驱动数量。计数包含停用记录及内置驱动。可修改显示名、联系人、备注或启用状态，不级联改动设备、驱动配置。
- 未被引用的品牌仍可经 API 改标识、删除；若后来的硬件写入仍指定旧 vendor，重新建立该精确标识对应的目录行。这是新目录记录，不把已删除旧记录的联系人等资料自动复活。
- 保留精确 vendor（含历史首尾空格），不做隐式改名、合并或格式清理；已有品牌资料、停用状态与时间戳不会被自动建档覆盖。独立 `ensureReferenced` 只用于目录补齐，运行时引用写入不得再把它与后续保存分开调用。
- 品牌标识的空值、纯空白、非字符串及超长输入被拒绝，避免利用旧接口的假值判断绕过改名保护。

## 边界与后续

本批无数据库迁移，无前端生产逻辑、设备协议、IP、接线或播放器改动；累计候选仍含此前音响、电源迁移 41/42。品牌管理页原本就禁止编辑标识，本批补上服务器端约束，防止旧客户端或直接 API 绕过。

事务约束覆盖上述运行时服务入口，不是数据库全局外键，不能保护绕开服务的手工 SQL 或第三方写库。迁移与运维脚本需离线受控执行并独立检查引用。多进程连接仍受 SQLite 锁协调，遇到锁冲突不能绕过校验强行保存；本批只验证单个生产应用 DataSource 中的服务队列，不声称多实例部署验证完成。

尚未完成的 C05 内容：品牌完整运行时 DTO、URL 安全规则、修订号/CAS、可信操作者与原子审计、无变化策略、滚动兼容退出、前端草稿及身份生命周期。当前顺序串行化**不等于**防陈旧编辑覆盖。

C09 的设备/驱动完整配置契约仍独立待办。硬件操作日志、控制器审计、网关 IP 传播和适配器缓存失效保持原来的后续步骤；不承诺这些后续步骤失败能回滚已提交的目录和硬件行。不以此次关联修复宣称整个硬件管理操作已全链路原子化。
