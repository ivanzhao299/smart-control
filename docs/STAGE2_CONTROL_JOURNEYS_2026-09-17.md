## 1. 根因与整改

### 浏览器登录

浏览器曾把客户端密码以 `sc.client.savedPassword` 明文保存在 `localStorage`，并在令牌失效后尝试静默重登。这使浏览器同时持有令牌和长期密码，身份来源不够收敛。

现在浏览器只持有服务端签名令牌、到期时间、服务器地址和与服务器绑定的用户名。启动迁移会清除历史明文密码；登录跳转只接受本地单斜杠路径，拒绝外部地址、协议相对地址、反斜杠和控制字符。原生壳的密码仍保存在系统加密存储中，且只在用户主动进行生物识别时取回。

### 灯光命令

原页面先改变开关或亮度，再异步发送请求；失败恢复分散在多个处理函数中，快速重复操作还可能让较早响应覆盖较新意图。

现在每个分区只允许一个在途命令，开关、亮度和批量操作共用同一事务边界。界面可以即时反馈，但只有服务端成功确认后才提交；失败时同时恢复开关和亮度，并保持其他分区可用。

### 大屏空闲或黑屏

播放器启动状态读取与 WebSocket 实时事件存在竞态：如果变更事件恰好在旧状态请求尚未完成时到达，旧实现因请求已在途而忽略刷新；随后旧响应把页面留在空闲状态，最长要等下一次 30 秒轮询。

播放器现在把在途期间收到的失效事件记为待处理。当前请求完成后立即再读取一次最新状态，直到没有新的失效事件。该修复覆盖三路播放器通道，避免实时投放被旧读结果压回空闲页。

## 2. 可重复的浏览器验收

一次性验收环境从全新数据库开始，通过正式首次管理员命令创建命名管理员，启动真实后端，并只把设备适配器替换为 MOCK。浏览器以生产部署前缀 `/control` 运行，覆盖：

1. 命名用户登录、页面返回、刷新和管理员会话保持。
2. 历史 iOS 登录数据迁移和浏览器明文密码清理。
3. 真实媒体上传、隐私访问和撤销。
4. 三路播放器 WebSocket 握手、变更事件与在途读取竞态。
5. 灯光真实 API 请求、单分区串行、成功确认和失败恢复。

测试只使用隔离数据库、隔离媒体目录和 MOCK 设备，不连接生产设备或生产数据。
