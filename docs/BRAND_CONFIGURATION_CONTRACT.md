## 权威源与写入边界

`brands` 关系表继续是唯一权威源；不新增业务副本。第 43 个迁移只增加 `config_revision INTEGER NOT NULL DEFAULT 1`。
完整旧链 42 迁移的逐字段对账保留品牌精确标识、联系方式、停用状态、时间戳及历史不规范 URL，不在迁移中静默清理。
模式漂移、非法历史版本失败关闭；重复执行不重置版本；未归档降级拒绝，恢复应使用代码/数据库匹配的独立备份。

品牌标识与硬件/驱动 vendor 的精确软关联规则保持不变。前端编辑既有标识不 trim、不开放改名；服务端继续拒绝被引用品牌改标识/删除。
未引用标识的 API 改名仍受版本与唯一性保护。引用建立与自动品牌建档维持同一事务，并增加来源为 `brand-reference:create` 的系统派生审计。
硬件审计回滚也通过品牌引用事务重建必要目录；回滚审计失败时品牌与硬件一起回滚。C09 的硬件完整契约仍未关闭。

## API

- `GET /brands`、`GET /brands/:id` 返回 `configRevision`。
- `POST /brands` 使用运行时创建 DTO；服务端也验证白名单，拒绝伪造操作人、版本、未知属性。
- `PUT /brands/editor/:id` 必须带 `expectedRevision`；`DELETE /brands/editor/:id?expectedRevision=N` 必须带版本。
- 所有写入只接受管理员；命名用户在 SQLite 写事务内再次核对角色和启用状态，排队期间被降权不能继续保存。
- 修改/删除使用 CAS；陈旧请求返回 `409 BRAND_CONFIG_REVISION_CONFLICT`，唯一标识冲突为 `409 BRAND_CONFIG_KEY_CONFLICT`，引用阻止为 `409 BRAND_REFERENCED`。
- 严格接口缺少/非法版本为 400，记录缺失为 404。无变化不增版本、不增审计，陈旧的无变化请求也不能假成功。
- 写入与审计同一事务。操作者来自服务器 Actor；客户端不得指定。审计 URL 去除查询和 fragment，避免存储签名参数；实际品牌 URL 保留供业务使用。
- Logo 仅允许 HTTP(S) 或 `/media/`、`/api/media/` 路径；官网仅 HTTP(S)。拒绝活动协议、凭据 URL、协议相对链接、反斜杠、空白/控制字符和越界媒体路径。

### 滚动兼容桥

旧 `PUT /brands/:id`、`DELETE /brands/:id` 继续接受缺省版本，但也经过 DTO、权限、原子审计和引用保护。
无版本删除不存在行保留旧幂等语义。**旧端缺省版本仍可能覆盖新值，不声明全部客户端已防陈旧覆盖。**
新管理页只调用严格入口。后端和迁移先发布，再发布前端；旧后端没有修订号时新前端禁写，不用猜测版本。

## 前端生命周期

`useBrandConfigEditor` 拆出目录读取、版本基线、提交冻结、冲突/不确定写入及身份生命周期。
只发一次保存；提交期间继续输入会保留为草稿并采用已确认的修订号。创建回执到达后继续输入转为编辑新记录，不再重复创建。
读取失败、无版本回执、保存失败/不确定结果均保留草稿并禁写；重新读取需确认，读取期间继续输入也不被覆盖。
另一人删除记录时保留草稿且保持禁写，不把原编辑自动变成新增。切换账号/服务器、页面销毁使晚到结果失效；删除确认框也绑定原身份。
已有编辑抽屉时禁用列表行写操作，避免暗中改变草稿基线。历史/草稿中的危险 URL 不渲染为链接或图片，但数据库原值不被自动修改。
