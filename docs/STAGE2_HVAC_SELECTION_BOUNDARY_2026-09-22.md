## 1. 本批目标

完成 P2-A26～P2-A29 后，`HvacPage.vue` 仍直接维护楼层筛选、空分区与未分组投影、分区卡片、选中集合、控制条共识状态以及全选/反选/分区选择。它们虽然不发请求，却同时被设备控制、目录写入和页面模板依赖，继续留在页面内会带来以下风险：

- 切换楼层时误清理其他楼层的选中项；
- 全选、反选和分区选择作用到隐藏楼层；
- 空分区再次被过滤，导致新建分区看似“没有保存”；
- 未知设备占位状态被当成真实读数，控制条显示虚假共识；
- 页面、分区卡和控制条分别计算同一份投影，后续行为逐渐分叉。

本批新增 `useHvacSelection.ts`，把只读视图投影和选择集合操作收敛到一个组合式用例。页面只负责渲染与连接已有的运行状态、控制和目录边界。

## 2. 收敛后的责任边界

组合式用例统一负责：

- 当前楼层的内机、分区、空分区、未分组数量、分组段落和分区控制卡投影；
- 选中内机、稳定 ID 集合、运行摘要及模式、风速、开关、温度共识；
- 单台切换、当前可见范围全选/取消、反选、清空和按分区切换；
- 楼层变化只更新可见投影，保留其他楼层已经选中的设备；
- 空分区保持可见但不能形成伪“已全选”状态；
- 未读到状态的设备不参与控制条共识；
- 分区改名后由同一响应式名称映射即时更新所有显示位置。

该边界不包含网络请求、数据库写入、目录保存或设备控制。已有 `useHvacRuntimeState`、`useHvacControls` 和 `useHvacCatalogActions` 的职责及接口保持不变。

`HvacPage.vue` 从 1300 行降至 1224 行。

## 3. 防回归契约

新增 5 项行为测试，并更新 1 项结构契约，覆盖：

1. 当前楼层全选、取消和反选均保留隐藏楼层选中项；
2. 分区选择可重复切换，空分区不改变选择且不显示已全选；
3. 控制条派生状态响应选择变化，并忽略未知设备读数；
4. 空分区、未分组、分区卡和分区名称保持一致且实时更新；
5. 楼层切换只改变视图，不重写选中集合；
6. 结构门禁禁止投影与选择编排回流 `HvacPage.vue`。

测试只操作 Vue 内存状态，不连接生产、数据库、网关或现场设备。
