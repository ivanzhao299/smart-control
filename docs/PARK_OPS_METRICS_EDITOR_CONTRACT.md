# 运营数据编辑契约与发布门槛

日期：2026-09-17。状态：本地实现和隔离验收完成，未部署 GK9000。

## 现有风险与本批效果

过去编辑器只读取业务数字，不带修订号保存；旧表单可能覆盖其他管理员的新修改。读取失败时还会自动载入出厂值并允许发布。本批为新版编辑器增加版本校验，并禁止在未成功读取当前版本时发布。

公开显示接口 `GET /api/park-ops-metrics` 的文档形状保持不变，因此已运行的 LED 页面无需同时升级才能读取数字。权威数据仍是 SQLite 的 `park.ops.metrics` 文档和修订历史；不新增表或迁移，不恢复 JSON 双写。

## 新版管理员接口

| 接口 | 请求 | 响应 data |
|---|---|---|
| `GET /api/park-ops-metrics/editor` | 命名管理员凭据 | `{document, revision, checksum, updatedAt}`，未发布时 document=null、revision=0 |
| `PUT /api/park-ops-metrics/editor` | `{document, expectedRevision}` | 同上，为本次实际保存结果 |

- DTO 拒绝缺失、null、负数、小数、字符串或不安全整数修订号；拒绝额外 envelope 字段及非对象 document。
- 文档沿用既有 256 KB、指标/文案字段数、类型和长度边界校验；不改变人车基线语义及显示刷新频率。
- 每次写入从数据库核对版本，使用原子比较并交换；首次创建也以 revision=0 检查不存在，避免两个首次保存互相覆盖。
- 相同内容不会增加修订。实际变更记录服务端验证的 `user:<id>:<username>` 和写入接口；请求体不能伪造操作者。
- 旧版本保存返回 HTTP 409 / `PARK_OPS_METRICS_REVISION_CONFLICT`；格式错误为 HTTP 400（业务文档错误带 `PARK_OPS_METRICS_INVALID`）。401/403 保持原身份边界。
- 页面不在冲突后自动重试或自动覆盖表单；保留草稿、暂停发布，管理员复制需要的内容后显式确认重新载入。
- 读取失败不再填入默认值；只有服务端确认从未发布过，才可用默认值开始编辑。账户切换时清空表单和修订，丢弃旧响应。

## 兼容桥梁与已知边界

旧 `PUT /api/park-ops-metrics` 暂时保留给已打开的旧 PWA，并新增真实操作者审计。该入口没有客户端版本，因此**不能提供跨旧、新编辑器的完整防覆盖保证**；发布后需确认管理员编辑器已更新，才能关闭兼容入口。本批不宣称这一兼容风险已消失。

退役门槛：新版前后端部署验收、管理员页面更新验证、旧入口访问审计；目标最迟 2026-10-17 完成退役评估。不得无限期保留或在没有客户端证据时直接宣称 API 收敛完成。当前没有自动定时删除或停用逻辑。

发布顺序必须先包含新接口的后端，再更新前端；新版前端对旧后端会安全地禁用运营数字发布，而不是退回无版本写入。按现有 GK9000 启动规则，后端重启会使三路播放回到待机，需单独批准维护窗口并重新推送内容。

## 验收证据

- 后端真实 SQLite 测试：命名审计、无变化抑制、旧修订拒绝、双服务首次写竞争、持久化版本而非缓存版本检查。
- 控制器/DTO 测试：管理员 guard、实际操作者、非法 envelope/修订号、409 不吞掉。
- 前端用例测试：版本绑定、防重复点击、读取失败、409 保留草稿、手动重载、账户切换与迟到响应、表单文案。
- 真实 Chrome + 全新临时 SQLite + Mock 后端：界面保存→第二管理员更新→旧界面保存得到 409→草稿保留→手动重载→断网时禁止发布。公开大屏仍收到原文档形状。
- 浏览器环境不等于 iPhone 真机或物理 LED；未操作生产配置，不把本地成功当成生产验收。
