# 阶段 2：PWA 路由与旧资源发布门禁审计

> 日期：2026-09-17
>
> 范围：P2-A1、P2-A2
>
> 结论：已发布并通过生产数据与新旧 PWA 资源核验；阶段 2 仍在进行中。

## 1. 本批目标

1. 消除主 PWA 页面路由、底部导航、分块预取和 API 预取的重复声明。
2. 保证发布后上一代 Service Worker 引用的分块仍可访问，避免 iPhone 从后台恢复时出现页面黑屏。
3. 全程不新增数据库迁移、不改写权威业务数据、不操作现场设备。

## 2. 完成内容

- 新增 `frontend/src/router/main-route-manifest.ts`，统一声明 11 个页面路由、9 个可见导航项、空闲/指针分块预取与 API 预取。
- 路由器和 `MainLayout` 从同一清单派生；两个 DALI 深链继续可用，后台入口保持独立。
- 删除 `App.vue` 中重复的空闲分块导入表。
- 修复部署脚本对 Workbox 清单格式的解析，同时接受 `"url":"..."` 与 `url:"..."`。
- 资源路径必须留在旧/新发布目录内；空清单、源文件缺失、路径越界和复制后缺失均失败关闭。
- 测试文件变更被识别为验证范围，避免纯测试变更触发不必要的全服务重启。

## 3. 缺陷根因与处置

P2-A1 首次发布暴露出旧资源门禁只识别带引号属性名，而真实 Workbox 压缩输出使用裸 `url` 属性。门禁因此提取到 0 个资源，并删除了上一代独有的 44 个分块。这不会改写数据库，但会让仍持有旧 Service Worker 的客户端请求已经不存在的页面分块。

在继续发布前，从只读回滚快照只追加恢复 44 个缺失资源，不覆盖当前同名文件。随后使用真实生成的 Service Worker 修复解析、路径限制与完整性校验，并通过标准受限网关发布。
