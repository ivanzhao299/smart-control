# 智慧中控生产事故与架构审计报告

日期：2026-09-16
范围：主 PWA、iPhone 拍照上墙、视频绑定/运营数据、GK9000 发布链、运行数据与数据库、后续产品化方向

## 1. 结论

本次三个现象来自三条不同故障链，均已找到可复现、可验证的根因：

1. **iPhone 提示“不是安全上下文”**：用户打开的是 HTTP 局域网入口。iOS/WebKit 只允许 HTTPS 或 localhost 调用网页相机；前端提示符合浏览器安全规则。应用原有 HTTP 入口无法靠 JavaScript 绕过这一限制。
2. **灯光、LED、音响等页面只剩底部图标、内容区黑屏**：主壳和底栏在首包中，业务页采用延迟加载。发布新版本时旧哈希资源被删除，仍存活的旧 PWA 随后请求旧业务页分包；Vite Preview 又把不存在的 JavaScript 路径回退成 `index.html` 并返回 200，浏览器因模块 MIME 类型错误中止路由挂载，所以只剩主壳。
3. **视频绑定检测线/ROI 编辑“丢失”**：正确配置并未被删除，仍在 `D:\smart-control-runtime\data` 及多份备份中。PM2 以进程名重启时沿用了旧环境，实际运行进程没有 `DATA_DIR`，后端便写入仓库内 `backend\data` 的另一份默认文件。读写路径分叉制造了“保存成功、重启后消失”的现象。

数据库没有发现同步丢失。生产现库与最近三份在线快照均通过 SQLite `integrity_check=ok`，37 张业务表行数完全一致；关键数据包括 38 个设备、81 个媒体记录、4 个场景、142 个场景动作、4 个用户、4215 条操作日志和 2984 条播放历史。

## 2. 已实施的修复

### 2.1 PWA 黑屏与发布兼容

- 生产静态服务对不存在的 `/control/assets/*` 返回真正的 404，不再把 HTML 伪装成 JavaScript。
- 路由错误识别增加模块 MIME 错误，并执行一次受限的 PWA 自愈：注销本应用旧 Service Worker、清除应用静态预缓存、使用防缓存参数重新载入当前路由。
- 白屏看门狗新增“主壳存在但内容区为空”的识别，覆盖本次“底栏正常、页面黑屏”的形态。
- 发布时保留上一代 Service Worker 引用的业务页分包，使已经打开的旧页面在新版本接管期间仍能完成一次路由加载。
- 前端健康门禁改为访问真实 `/control/` 入口，继续拉取入口 JavaScript并校验 JavaScript MIME 类型，同时确认缺失资源返回 404。

### 2.2 iPhone HTTPS 相机入口

- 使用现有受信任证书域名 `https://park.cnjinhu.com/control/` 提供同源 HTTPS 入口。
- `/control/`、`/control/api/`、`/control/ws/` 按路径转发到 GK9000，不占用该域名原有根站和 `/api/`。
- 前端按代理主机选择 API 路径，避免安全入口误连该域名上另一套系统的 API。
- HTTP 旧入口检测到非安全上下文时显示“打开安全版并拍照”，不传递登录令牌；用户首次需要在安全入口重新登录并重新添加到主屏幕。
- 继续使用 `getUserMedia + canvas` 的页内取景方案。没有恢复曾导致 iOS standalone PWA 原生相机进程闪退的 `input capture` 路径。

### 2.3 运行数据不再分叉

- 后端建立唯一运行数据目录解析器：显式 `DATA_DIR` 优先；Windows 即使环境变量意外缺失也固定回退到 `D:\smart-control-runtime\data`，不会再写进 Git 工作区。
- 视频绑定、运营指标、运营大屏控制三处统一使用该解析器。
- 视频绑定保存改为临时文件落盘后原子替换，并保留上一份 `.bak`；主文件损坏时可读取备份恢复。
- 运营指标读取增加 `.bak` 回退；运营大屏控制状态也改为原子写与备份。
- 发布脚本使用 ecosystem 配置重新协调 PM2 进程和环境，不再仅按进程名重启。
- 发布脚本自身更新采用“两次发布”引导：第一次把新版脚本落盘，紧接着的发布再由新版脚本执行环境协调和旧数据恢复，避免误以为自更新脚本能在同一进程中改变已加载逻辑。
- 发布迁移发现受保护目录缺少主文件时，会校验并恢复仓库内遗留的有效 `.json.bak`。这会恢复此前遗漏的运营指标文档，同时不覆盖更新的数据盘文件。
- 运营大屏控制接口仅保留状态读取为匿名；翻页、自动播放和刷新等写操作重新进入全局登录门禁。

## 3. 部署门禁审计

### 已修正的不合理点

| 原门禁/行为 | 风险 | 修正 |
|---|---|---|
| `pm2 restart <name> --update-env` | 只继承当前 shell 与旧 PM2 状态，不能保证 ecosystem 新变量进入进程 | 每次从 ecosystem 配置启动/更新并保存 PM2 状态 |
| 前端发布清空全部哈希资源 | 打开的旧 PWA 在版本切换时必然可能请求 404 | 保留上一代 SW 引用的资源 |
| 缺失 `.js` 回退为 `index.html` 200 | 错误被伪装成成功，路由只留下黑内容区 | 缺失构建资源强制 404/no-store |
| 健康检查只看静态站根路径 200 | 无法证明入口模块可执行，也无法发现错误 MIME | 校验 `/control/`、入口 JS、MIME 与缺失资源 404 |
| 运行数据迁移只扫描 `*.json` | 只剩 `.json.bak` 的有效数据无法恢复 | 校验后恢复缺失主文件，绝不覆盖数据盘现值 |
| 运营大屏控制器整类 `@Public` | 未登录用户可发翻页/刷新写指令 | 仅 GET 状态公开，POST 写操作要求身份 |

### 保留且验证为合理的门禁

- 发布前做 SQLite 在线备份并执行完整性校验，失败即停止发布。
- 禁止对生产工作区做广泛 `git clean/reset`；只隔离与目标提交确实冲突的未跟踪文件。
- 数据库、日志、备份、运行时数据均列为受保护路径。
- 数据库迁移与代码发布绑定；迁移失败禁止继续。
- 发布后校验 PM2 进程、端口占用者、进程启动时间、健康接口与重启稳定性。

## 4. 仍需推进的产品化改进

### P0：近期完成

1. **移除源码中的设备凭据默认值**：摄像机/NVR 凭据应进入生产密钥文件或受限配置表；读取 API 默认脱敏，更新密码使用“留空即保持原值”的语义。
2. **给 HTTPS 公网入口增加可用性监控**：每分钟检查证书、`/control/`、健康接口和 WebSocket 握手；只有异常持续时告警。
3. **建立 PWA 升级端到端测试**：保留旧页面，发布新版本后依次打开灯光、LED、音响，验证旧客户端过渡、新客户端接管和离线恢复。
4. **为运行 JSON 增加版本与审计记录**：每次保存记录操作者、时间、摘要和前后版本，可在后台一键查看和回退。

### P1：下一阶段

1. **统一运行文档存储层**：将三套同步文件读写收敛为 `RuntimeDocumentStore`，统一 schema 校验、原子写、锁、备份、恢复和审计。稳定后可迁入 SQLite 事务表。
2. **发布目录版本化**：前端构建发布到 `releases/<commit>`，完成验证后原子切换 `current`；保留最近两版并延迟清理，减少停机和文件占用问题。
3. **拆分大型页面与部署脚本**：按灯光、媒体、音频、视频绑定拆出领域组件；将超长 PowerShell 脚本拆成可测试模块，降低一次修改影响整条发布链的概率。
4. **消除重复预加载逻辑**：路由预取目前分布在应用入口和主布局，应由一份路由元数据生成，避免新增页面后漏配或重复请求。
5. **播放器失败可见化**：媒体/文档渲染失败不应保持纯黑，应显示错误原因、重试和回到默认画面的操作。

### P2：成熟度建设

1. 建立设备控制命令的统一超时、幂等键、重试和熔断策略。
2. 给 API DTO 做全量运行时校验，禁止控制器直接接受宽泛对象。
3. 增加配置与数据库的灾难恢复演练，定期验证备份能恢复，而不仅是“文件存在”。
4. 建立前端错误聚合：记录版本、路由、资源 URL、Service Worker 状态和设备型号，后台可直接查看黑屏/崩溃证据。
5. 统一文档中的公网域名、端口和部署拓扑，淘汰已经失效的旧入口说明。

## 5. 验收标准

- iPhone Safari 从安全入口打开时 `window.isSecureContext === true`，允许申请摄像头权限并完成拍摄、预览、上传与上墙。
- 灯光、LED、投影、音响、空调、电源、媒体、状态页逐页打开，内容区不能为空；不存在的资源返回 404。
- 生产 PM2 后端环境包含外置 `DATA_DIR`，启动日志显示从数据盘加载视频绑定配置。
- 自定义检测线和 ROI 与数据盘文件一致；重启后端、重启主机、再次发布后仍保持。
- 运营指标主文件恢复到数据盘；数据库现库和发布前后快照均通过完整性校验且关键表计数无异常下降。
- CI 的后端测试、前端类型检查、前后端构建、生产发布验证全部通过。
